## 一、我们要做什么（一句话总纲）

做一个**能发到 npm / 公开仓库的 DSH 原生插件**，里面修两条**地位平等**的"水管"，但在 DSH 模型选择器里**合成一组**、靠前缀区分；装好就一直在，日常只剩"选模型、发消息"两个动作，不用每次手填 `baseURL`、手加模型。

- **两条通道，地位平等、无主次**：一条花妙手客户端赠送的 Credits，用上 `glm-5.2`、`glm-5.1`、`deepseek`、`kimi` 等妙手自有模型；另一条接官方 API 的 `LongCat-2.5`，想用时随时能选。（"主目的/同时"这类词只描述当初的立项动机，不表示优先级；优先级口径见第二节与第六节末）

这解释了"官方明明有零代码方案，为什么还要自研插件"：要的不是"能用上 LongCat"，而是**把配置自动化 + 把两条通道统一进 DSH**。这正是 `temp/` 里三个插件存在的意义——它们做插件是为了"自动注册 + 统一入口"，不是为了让模型能跑。

第一版只求**稳定能用**、个人自用、Windows 为主，增值功能以后再说。**完整功能清单见第六节（唯一权威来源）**；下文涉及功能一律引用其编号（F#）。

## 三、两条通道是什么（大白话版）

> 下表是"两条水管有什么不同"的**背景对比**，不是功能清单；要实现的功能以第六节 F3（通道 A）/ F4（通道 B）为准。

| | 通道 A（官方 API） | 通道 B（妙手客户端转发） |
| --- | --- | --- |
| 走法 | DSH → 插件 → 官方 `api.longcat.chat` | DSH → 插件 → 读本机妙手登录态 → 发给妙手上游 |
| 请求要不要"翻译" | **基本不用**，本来就是标准 OpenAI 形状，插件只管带上 Key、注册好 provider | **要双向翻译**：把 DSH 请求改写成妙手私有格式（`agentModeConfig` 一类），再把 SSE 响应翻译回 OpenAI 形状 |
| 花谁的钱 | 官方 API 的钱，按 Token 计费 | 自己账号的赠送 Credits，按"次对话"计 |
| 能用的模型 | 目前只有 `LongCat-2.5` | `glm-5.2` 等客户端目录里那一批 |
| 运行参数可调 | 深度思考二值开关（F9）；**无上下文档位选择**（决策 4b：只针对 B） | 深度思考二值开关（F9）+ **逐模型上下文档位（F10）** |
| 工作量 | 薄，几乎直通（所以先做） | 厚，是主要活儿：凭据读取、token 刷新、协议翻译、错误分类、档位读出与注入都要写 |

两条**并存、互不干扰**：选 `catpaw/` 走客户端额度，选 `longcat/` 走官方计费，不会串账。

## 四、装好之后长什么样（"无感"的具体含义）

> 下面是**三阶段全部完成之后的最终态**，不是阶段一的样子；阶段一只有 `longcat/` 一条、`catpaw/*` 是占位态（见第九节）。

DSH 模型选择器里出现**一组**，大概长这样：

```
catpaw/glm-5.2        ← 花客户端赠送 Credits
catpaw/glm-5.1
catpaw/deepseek-…
catpaw/kimi-…
longcat/LongCat-2.5   ← 花官方 API 的钱
```

选一个、发消息、完了。设置页只配**一次**（F5 那张卡）：填 LongCat API Key、确认/登录本机妙手账户、**两个 tab 各把「深度思考」开关拨到想要的状态**（F9，二值、无多档）、**在妙手 tab 给每个模型各选一个上下文档位**（F10，当前 200K / 500K / 1M，逐模型）；之后登录态自动发现并刷新、开关值与档位值随重启 DSH 也还在（F1/F7）。卡片的参考来源与分工见第八节 A。

**两个一次性前提免不掉**（"无感"不等于凭空变出凭据，但都是"一次"、不是"每次"，之后一直记住、自动恢复，就是插件要干的活）：
1. 本机装并登录过一次妙手客户端（Windows）；
2. 去 longcat.chat 控制台申请一次 API Key，填进设置卡（F5）或用环境变量注入（F7），二选一。

## 五、"并成一组"在技术上意味着什么（关键设计）

两组并一组，**不是真的只有一个上游**——两条水管目的地完全不同（一个去 `api.longcat.chat`，一个去 `catpaw.meituan.com`）。所以插件内部要做一个**"看前缀分流"的小开关**：

1. DSH 看来只有一个 provider；
2. 请求先到插件的本机回环服务（loopback shim）；
3. 插件看模型 id 的前缀：
   - `longcat/` → 带 Key **直发官方**，几乎不改形状；
   - `catpaw/` → 把请求**改写**成妙手私有格式后发出，再把 SSE 响应**翻译回**标准 OpenAI 形状；
4. 统一把结果交回 DSH。

**好处**：一屏看全、不用切 provider。
**代价**：这个分流架子**第一步就得搭好**（哪怕当时只有 `longcat/` 一条），否则第二步加 B 要返工。前缀也不能混用。
**组名**：暂沿用仓库名 `dsh-connect-catpaw`（待定，不影响前缀方案）。

这套"回环 shim + 进程内密钥 + 按模型分流"的做法，正好来自 `temp/` 三个插件的 `shim.ts` / `adapter.ts` 骨架，可直接学。

**读数纪律（决策 1/2 后）**
- **官方侧无余额读数**：整条功能已舍弃，不显示、不编造、不拿 `pricing` 单价或 Token 用量凑数；也不放"读不到"的提示位（那是给"想读但读不到"准备的，现在是不读）。用户需要余额时自行去官网查询；
- **官方侧参数实时准确**：模型清单与参数走 `GET /v1/models` + `GET /v1/models/{model}` 活取；接口失败/401 时才回落到静态兜底值，并**如实标注"回落/兜底"**，不把兜底值冒充实时结果；
- **模态字段口径**：[longcat.md](longcat.md) §3 指出模型详情 `architecture.input_modalities` 示例为 `["text"]`，与视觉理解章节及官方 DSH 配置页"支持图片"存在口径差异。**实现以 `supported_parameters` / 官方 DSH 配置页为准，不凭 `architecture` 单字段下"纯文本"结论**；静态兜底沿用官方 DSH 配置页盖章的 `input:['text','image']`；
- **妙手侧**：剩余 Credits 按"次对话"计，与官方侧参数/单价**分开标、不换算**，绝不放一个数字里；模型列表各是各的、互不混显；
- **⚠️ 两个「1M」不要混**：官方 tab 那个只读的 `contextWindow = 1M` 是**模型能力上限的展示**；妙手 tab 可选的「1M 档」是**用户主动选的上下文预算/档位**。二者数值像、含义完全不同，**绝不能混成一个字段，更不能拿官方的 1M 去当妙手的档位**；
- **档位读出如实标注**：F10 档位来自本机配置/上游接口时标"实时读出"，读不到/用兜底时标"不可用/兜底"，**不冒充实时读来的、不写死三档当最终事实**（见「上下文档位纪律」）；
- **展示位置唯一（澄清，决策 3/4 后）**：所有**读数/展示信息**（Credits / 模型列表 / 参数 / 档位）**只待在 F5 设置卡的两个 tab 里**；对话框右下角、输入框附近、任何胶囊/徽标位置**一律不显示任何读数、也不放任何推理/档位/设置交互框**——聊天界面保持干净、不影响观感。**这条禁的是"聊天界面上的展示与操作控件"，不禁止在设置卡内部放操作开关/选择器**（F9 的两个思考开关、F10 的逐模型档位选择器正是放在设置卡内，不在此禁令范围内）。

**思考开关纪律（F9 / 决策 3，唯一权威）**
- **只有二值"开/关"，两条通道都没有多档**：不做 `low`/`medium`/`high`/`xhigh`/`max` 之类推理等级，不做逐会话/逐模型/每轮切换；开关只表达"是否开启深度思考"；**这句"无多档"特指推理等级/深度思考，不禁止一切三态控件**（F10 的 200K/500K/1M 是上下文档位，不是推理等级，不受此限）；
- **两个开关各自独立、互不联动**：官方 tab 的只影响 `longcat/*`，妙手 tab 的只影响 `catpaw/*`，改一个不动另一个；
- **配一次、长期生效**：开关值存本机配置（F7），重启 DSH 也还在；因使用频率很低，不做聊天界面快捷切换；
- **默认值跟随上游默认**（LongCat 默认开思考、妙手默认跟随客户端），不强行替用户改；若日后要改默认值须单独拍板，不得各实现自行决定；
- **放设置卡内、不碰聊天界面**：见上一条"展示位置唯一（澄清）"；
- **生效方式**：开关是"偏好"，真正起作用在发请求前——官方通道 `chat()` 注入 `thinking:{"type":"enabled"|"disabled"}`（[longcat.md](longcat.md) §4，随每次请求带、不是上游记住一次）；妙手通道把同一二值翻译成私有请求体 `agentModeConfig` 一带的形状（形态不同、分别处理）；
- **与三阶段的边界**：阶段一里**官方通道的开关要真正生效**（A 是阶段一做完的）；**妙手侧开关在阶段一只做"UI 有控件 + 配置能存 + 明确标注待实现"**，真正注入私有请求体留到阶段二随 B 的真实逻辑一起替换（不破坏"阶段一 B 留白、外壳/GUI 全部做完"）。

**上下文档位纪律（F10 / 决策 4b，唯一权威）**
- **真读出、不写死**：档位从妙手客户端本机配置 / 上游接口**读出**；当前已知三档 200K / 500K / 1M 只是"已知事实"，实现按读出结果动态显示（上游只给两档、或多给一档，都按读出的显示），读不到就如实标注"不可用/兜底"，不编造、不假装是实时读来的；
- **逐模型一个档位**：模型列表**直接显示所有读到的模型**（不做启用/禁用勾选），每一行配自己的档位选择器；每个模型各自读、各自选、各自存，不假设所有模型档位一样；
- **只针对通道 B**：官方 A 保持现状（只读参数 + 深度思考开关），**不加档位选择**；两个「1M」的含义区分见上；
- **放设置卡妙手 tab 内、不碰聊天界面**：见"展示位置唯一（澄清）"；
- **配一次、长期生效**：逐模型档位值存本机配置（F7），重启 DSH 也还在；不做逐会话/每轮切换；
- **与「不做模型勾选管理」的边界**：那条只禁止"勾选哪些模型启用/禁用"那种管理，**不禁止**对任一模型的具体参数（上下文档位、以及以后同类参数）做配置；
- **与 F9「无多档」的边界**：那句特指推理等级/深度思考，不禁止 200K/500K/1M 这类三态档位；F10 与 F9 互不干扰；
- **生效方式与阶段二裁定（把判断权交给 Lead，但原则公开）**：档位值是"偏好"，用户期望走 **(a)**——注入发给妙手的私有请求体、随每次请求带；但 **(a) 是否真有可控字段且确实生效、以及档位能否真读出来，都留阶段二用只读探针 + 真账号实测**，由 Lead 据实裁定：
  1. **(a) 证实可行** → 按 (a) 做，档位值注入私有请求体；
  2. **(a) 不可行** → 不硬凑、不假装生效；退一步判断 **(b)**（DSH 本地"上下文预算"，只决定本地何时压缩对话、不发给上游）是否还能达成"用户调档位"的意图：能，就退 (b) 并**明确告诉用户这是本地预算、不是发给妙手的**；连 (b) 都不成立或会误导，就如实标注"该档位暂不可用/未实现"，控件保留但说明原因；
  3. **无论哪种**：实测过程与结论写进取证文档（证据分级、失败过的猜测也记），**最终裁定明确告知用户并写进报告，不静默改需求**（从 (a) 退 (b) 属语义变化，用户有权知情）；一句话——**优先 (a)、实测为准、退路有据、结果公开、不编造生效**；
- **与三阶段的边界**：阶段一里**逐模型档位控件 + 档位值持久化 + 占位档位列表（已知三档顶着、标注"占位/待实现"）全做完、可点可存**，但"真读出档位"和"应用档位到 (a)/(b)"留白、标注待阶段二；阶段二随 B 真实逻辑一起替换（探针实测 + 裁定 + 应用）；阶段三验收档位读出/回落标注、逐模型持久化、两通道不串、与 F9 互不干扰。

**明确不做（以后再说 / 已决策舍弃）**
- **官方余额/用量读取显示**（**决策 1 完整舍弃**，非"以后再说"）：插件不读、不显示、不研究控制台非公开接口；用户自行去官网查询；

**A. 外壳与交互 → 以 `dsh-connect-workbuddy` 为准（特别是设置页那张卡）**

- 插件骨架：`index.ts` 的 apply 装配、provider 自动注册、`settingsNamespaceOf` 探测、`cordis.patch.yml` 挂载、`package.json` 的 `dsh` 字段、tsdown/vitest 构建测试、发布流程、隐私门禁；
- 交互层：设置页卡片长相、分栏/tab 组织、本地配置怎么存怎么读、槽位怎么挂、错误提示怎么给——**都按 workbuddy 的设置卡来**，风格统一、也支撑"无感"（一次填完就一直在）；
- **点名的重点**：设置里那张卡就是功能清单里的 **F5**——一张卡内**两个独立 tab**（官方 API / 妙手），分别放「填官方 API Key」与「登录/验证本机妙手账户」入口，不拆成两个插件或两个页面。它的规格以第六节 F5 及"设置卡显示契约"为准，本节只说明**长相与交互照 workbuddy 抄**（workbuddy 本身也是双 tab 外壳，我们按通道分、不按地区分）。

**B. 功能实现 → 以 `Agent2API` + "解析 agent 软件（尤其针对妙手）"的部分为准**

- **妙手协议（通道 B 主力）**：主要看 `Agent2API` 的 "CatPaw provider" 行为（第三方沿用旧名 CatPaw，即妙手），以及专门针对妙手的逆向项目——`thief-neko`（协议细节最全）、`catpaw-bridge`（加解密）、`catpaw2api`（已归档）。具体是：怎么读本机 `state.vscdb` 登录态、`Catpaw-Auth` 等请求头怎么拼、`/api/gpt/openai/stream` 的私有请求体怎么改写、SSE chunk 怎么翻译回标准形状、token 怎么刷新、额度怎么读；**F10 的档位读出、私有请求体里上下文字段与 (a) 可行性，也在阶段二的探针实测里一并确认**（第十节第 10 条）；
- **另外三个插件里"解析 agent 软件"相关的部分**：指 `temp/` 里 qoder / trae / workbuddy 中**专门干"解析客户端、把客户端额度接出来"的那些模块**——`upstream.ts`、`credentials`/`auth.ts`、`shim.ts`、`probe-*.mjs`、`messages.ts` 这类"跟上游打交道"的代码，用来学**怎么把这套事做成 DSH 插件里稳定的模块**（只读凭据、回环 shim、错误分类、probe 取证纪律）；**不是**它们的账号池/签到/徽标增值部分（第一版不做）；
- **通道 A（官方）**：几乎不需要"解析 agent"；对应功能清单的 F1 / F3 / F6（官方侧的**模型列表 + 模型详情实时参数**，**不含余额**）/ **F9 官方侧思考开关**（`chat()` 注入 `thinking:{"type":"enabled"|"disabled"}`），接口事实以 [longcat.md](longcat.md) §2/§3/§4 为准（`GET /v1/models`、`GET /v1/models/{model}`、`thinking` 字段），外壳复用 F5 那张卡；**F10 只针对 B，官方侧不实现**。

**C. 两条贯穿的边界（与第六、七节一致）**

- **"参考" ≠ "复制源码"**：`Agent2API` 是 AGPL-3.0，公开发仓库前提下仍是**只看行为、独立重写、写 `THIRD_PARTY_NOTICES`**；workbuddy 等是 MIT，同样只取结构与思路；
- **范围以第六节功能清单为准**：F5 那张卡是必须做的交互、不算增值；整套增值（账号池/签到/**模型启用禁用勾选管理**等）列在第六节"明确不做"——但**逐模型参数配置（F10）不算增值、是必须做的**。

证据、来源、协议细节见 [CATPAW-调研报告.md](CATPAW-调研报告.md)。

## 九、实现顺序：三阶段开发计划

> 整个代码开发分**三个界限干净的阶段**（见下）。阶段是"什么时候做完哪一块"的**顺序**，不是功能定义——功能以第六节 F# 清单为准；F3 与 F4 **逻辑无主次**，仅因 A 简单而先做。
> 「阶段完成判据」只判断该阶段能否收尾；**真正的全量验收在第三阶段**，不与前两阶段的小自检混淆。

### 阶段一 · 插件骨架 + 通道 A + 通道 B 留白占位

**把除"通道 B 真实逻辑"以外的所有部分全部实现**，特别是**插件构建**与 **GUI 显示交互**：

1. 工程骨架（照 `temp/` 的 `package.json` / `cordis.patch.yml` / tsdown / vitest），**构建体系本身要能跑通、能产出产物**；
2. F1 自动注册与模型目录、F2 按前缀分流的架子（此时只有 `longcat/` 一条，但架子要留对）；
3. F3 通道 A 直发官方、F6 的官方侧部分（**模型列表 + 模型详情实时参数**：接 `GET /v1/models` 与 `GET /v1/models/{model}`，见 [longcat.md](longcat.md) §2/§3；**不实现任何官方余额读取**）、**F9 官方侧思考开关真正生效**（`chat()` 按二值开关注入 `thinking:{"type":"enabled"|"disabled"}`，见 [longcat.md](longcat.md) §4）；**F10 只针对 B，官方侧不实现**；
4. **F5 设置卡完整实现**：照 `dsh-connect-workbuddy` 风格的一张卡、**两个独立 tab 都能显示、能切换、能交互**——官方 tab 含「模型列表 + 实时参数」展示位、Key 入口、**一个「深度思考」二值开关**（**无余额栏、无档位选择器**）、妙手 tab 含「Credits + 逐模型列表（**每行带上下文档位选择器**）」展示位、登录验证入口、**一个「深度思考」二值开关**、手动刷新控件——两个思考开关都是二值、互不联动；档位选择器逐模型可点可存；这是本阶段点名必须做完的 GUI 部分；
5. F7 Windows 本地数据与配置（**含 F9 两个开关值、F10 逐模型档位值的持久化**）、F8 工程与门禁（`THIRD_PARTY_NOTICES`、隐私/PII 门禁）；
6. **命名**：用户可见文案一律「妙手」，技术标识原样保留（第二节「命名约定」）。

**通道 B 留白占位（空白实现）**：B 相关的接口、路由分支、妙手 tab 的位置、数据结构**全部先搭好立在那儿**，但真实逻辑是空的、明确标注"待实现"。要点：
- **不等于界面残缺**——妙手 tab 要画得出来、点得动、切得过去，只是显示占位状态/假值（按第七节隐私约束，占位一律用假数据，绝不写真账号数据）；不能因留白让界面崩、也不能把 tab 藏起来；
- **占位内容**：妙手 tab 的剩余 Credits、逐模型列表、以及**每行档位选择器（用已知 200K / 500K / 1M 三档占位、标注"占位/待实现"）**都用**假值/静态占位**顶着，并如实标注"占位/待实现"，不冒充真实接口响应（见第十节第 4 条、第 10 条）；
- **F9 妙手侧开关在阶段一的处理**：开关控件、二值状态、配置持久化**都要做完并可点可存**，但其"把值注入私有请求体"这步是**留白**——标注"待阶段二随 B 真实逻辑一起替换"，不在阶段一实现；
- **F10 在阶段一的处理**：逐模型档位控件、档位值持久化、占位档位列表**都要做完并可点可存**，但"从本机配置/上游真读出档位"和"应用档位到 (a)/(b)"是**留白**——标注"待阶段二探针实测与裁定后替换"（见「上下文档位纪律」）；
- 也不是"不做 B"——空壳先立好，第二阶段只做"替换"，**不再动外壳、不返工**。

- **阶段完成判据**：插件能构建出产物；装进 DSH 后 `longcat/LongCat-2.5` 自动出现在选择器、能完成一次对话、官方 tab 的**模型列表与参数由两个 GET 接口实时取回且正确**（接口失败时回落静态兜底并标注"回落"）、重启后配置还在；**官方「深度思考」二值开/关均能正确注入 `thinking` 字段并生效**；**官方 tab 无任何余额栏、无档位选择器**；设置卡两个 tab 都能正常显示与切换、**两个二值开关都能拨动且各自存住值**、**妙手 tab 每行档位选择器都能拨动且逐模型存住值**、妙手 tab 显示占位态且其开关/档位明确标注"待实现"；**用户可见文案为「妙手」、技术标识（前缀/域名/头）未改**。

### 阶段二 · 通道 B 功能实现补充

**在阶段一的地基上，只做一件事：把阶段一里通道 B 的留白替换成真实代码实现**（F4 全量 + F6 的妙手侧 Credits 真实取数 + **F9 妙手侧思考开关的注入实现** + **F10 档位真读出与应用**；**通道 A 的官方模型列表/详情接口、官方思考开关、官方侧无档位，均在阶段一做完，本阶段不动**）：

1. Windows 凭据读取（只写形状不写真值）+ token 自动刷新；
2. 私有请求体改写、SSE 响应翻译回 OpenAI 形状、错误分类；**把阶段一留白的 F9 妙手二值开关值翻译成私有请求体 `agentModeConfig` 一带的对应形状并注入**（形态与官方 `thinking` 不同，单独处理）；
3. 客户端 Credits 读数（`/api/user/limit`）、妙手 tab 手动刷新的真实逻辑；**用真账号抓包确认「支持的模型列表」能否活取**（第十节第 4 条）：有可拉取的目录接口就活取，没有就沿用静态清单并如实标注、不冒充接口响应；把 `catpaw/*` 并进同一组（F2）；
4. **F10 探针实测与裁定（第十节第 10 条）**：用只读探针 + 真账号，① 确认每个模型的上下文档位**能否从本机配置/上游接口真读出**（读出就动态显示、读不到就如实标注兜底）；② 实测 **(a) 是否真有可控的上下文字段且确实生效**；③ 由 Lead 按「上下文档位纪律」据实裁定走 (a) / 退 (b) / 如实标注不可用，并把实测过程、结论、最终裁定写进取证文档与报告、**明确告知用户、不静默改需求**；④ 把档位值应用到裁定后的那条路上。

**外壳、GUI、构建、通道 A 一律不动**——阶段一已做完并验过；F9 妙手开关、F10 档位选择器的**控件与配置在阶段一已做完**，本阶段只替换"注入/读出/应用"这几处留白。

- **阶段完成判据**：`catpaw/glm-5.2` 等能稳定跑通、花的是客户端额度、两条通道互不串账、前缀路由不混用；妙手 tab 显示真实**剩余 Credits**/模型列表、手动刷新生效（官方 tab 始终无余额栏、无档位选择器）；**妙手「深度思考」二值开/关均能正确翻译成私有请求体并生效**，且与官方开关互不联动；**逐模型上下文档位按读出显示（或如实标注兜底）、裁定结论已落地并生效、逐模型值重启后仍在**；裁定结论与实测证据已写入报告并告知用户。

### 阶段三 · 插件全量测试验收

**所有开发完成之后**的独立收尾阶段：做**全方位测试**，目标是**主动找出可能的 BUG 并修复**，修完复测，不是"跑一遍绿就结束"。

## 十一、收到人工指令后，第一步做什么

按参考插件的纪律，**动手阶段从这里开始**，顺序不跳：

1. 写 `scripts/probe-*.mjs`（只读、脱敏、直接 import 生产源码、凭据只从环境变量读、绝不落盘），先验证通道 A 的连通、模型列表 `GET /v1/models` 与模型详情 `GET /v1/models/{model}`（决策 2 纳入的两个接口，事实见 [longcat.md](longcat.md) §2/§3）；**顺带确认 `thinking` 二值字段的请求体形状**（决策 3 / F9，官方侧，见 [longcat.md](longcat.md) §4）；**不探测任何余额接口**（决策 1 已舍弃）；
