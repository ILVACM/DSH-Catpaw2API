# DSH-CatPaw 插件设计（最终结论）

> 本文件为 P3 整理后的**最终设计结论**，由阶段一/二/三的过程文档整理而来，过程文件已清理。
> 配套：[探针结论](probe-findings.md) · [实现记录](implementation.md) · [官方 API 参考](longcat.md)

## 0. 目标

**复用本地「妙手」软件客户端的免费模型通道（LongCat-2.5），让 `catpaw/*` 在 DSH 里能真实对话。**

唯一价值：妙手的**免费额度**（`creditCost = 0.00000000`）。
通道 A（官方 LongCat API）已可用；两条通道同属一个模型选择器组，靠前缀区分。

---

## 1. 角色边界：施工队模式（已由实测确认，不可动摇）

> **妙手是「自带工具箱、自己把活干完」的施工队；DSH 是「业主 + 监工」。**

**为什么采用这个模式**：追加探针实测证明「由 DSH 接管工具调用」这条路线走不通 ——
妙手自带 27 个工具、不接受外部 `tools`、6 种权限模式都拦不住执行（详见 [探针结论](probe-findings.md)）。

| 层 | 谁负责 | 具体内容 |
| --- | --- | --- |
| **怎么想、怎么做** | **妙手** | 思考、选工具、执行、拿结果、继续生成，一条龙在它内部完成 |
| **在哪儿干** | **DSH（关键）** | 通过请求头指定工作目录，与 DSH 会话工作区**对齐**（§2） |
| **能不能干** | **DSH** | 决定是否放它进某个目录（会话/审批层） |
| **干了什么** | **DSH（部分）** | 从 `tool_execution_*` 事件做事后审计；看不到中间思考 |
| **几个工地、干多久** | **DSH** | 会话编排、上下文长短、何时压缩/重置 |

> 施工队模式是阶段二的「宪法」：妙手负责"怎么干"，DSH 负责"在哪儿干、能不能干、干了什么、几个工地"。

---

## 2. 🔴 工作目录对齐（本模式的前提，必做）

**实测**（2026-11-12）：

| 请求方式 | 妙手实际在哪个目录干活 |
| --- | --- |
| 不指定目录 | 它自己的安装目录（列出 `妙手.exe` 等） ❌ |
| 带 `x-catpaw-directory` 头 | **DSH 指定的目录**（正确列出仓库文件） ✅ |

**实现要求**：

1. 每次 `agent.start` 必带：
   ```
   x-catpaw-directory: encodeURIComponent(<DSH 会话工作区绝对路径>)
   ```
2. 目录来源：宿主把实时工作目录**强制写进 system prompt**（`required: true`）：
   ```
   Current working directory: "D:\...".
   ```
   shim 从 `messages` 里正则提取该行并 `JSON.parse` 还原。
3. **拿不到工作区时拒绝调用并返回可见错误**，绝不退回"不传目录"。
4. 不做"已隔离"的承诺：是否有能力访问目标目录之外未实测。

> 不对齐 = 它干的活落在错误位置，而所有人都以为改的是当前仓库 ——
> 这是最严重的一类「看起来成功、实际改错地方」。

## 3. 技术路径（已实测跑通）

| 步 | 动作 |
| --- | --- |
| ① 服务发现 | 按 `catpaw-cli` 进程 PID 定位监听端口（**端口动态**），探 `GET /` 含 `CatPaw Agent Server`；静态段兜底 |
| ② 指定模型 | `PATCH /api/admin/config`，body **只写 `{model: 10002544}`**，读回确认（`GET /api/config` 404 属正常） |
| ③ 发消息 | `POST /api`，JSON-RPC 2.0 `agent.start` + `stream:true`，带目录头 |
| ④ 收流 | SSE：`model_chunk`→文本、`model_end`→模型名、`tool_execution_*`→审计、`agent_end`→`creditCost` 守卫 |

事件映射表、端口范围、`PATCH` 键白名单等细节见 [实现记录](implementation.md)。

## 4. 设置页 GUI

**tab 名**：`本地客户端通道复用`（中英文统一；技术标识 `catpaw/` 原样保留）。

**卡片内容**（原有额度/档位/思考开关/登录/占位提示**全部删除**）：

| 行 | 内容 |
| --- | --- |
| 1 | 当前模型名称 |
| 2 | 是否可用（状态检测） |

外加：
- **人工刷新按钮**
- **风险提示**（必须写）：「该通道的模型会自行读取工作目录内文件并执行命令，其工具调用不受 DSH 控制。」

**状态检测行为**：
- 打开设置页**自动检测一次**；点刷新重新检测
- 三态：`检测中…` / `✅ 可用` / `❌ 不可用 — <原因>`
- **不做假状态**：检测失败必须显示具体原因，不假报可用

## 5. 模型选择器契约

**分组标题**：`catpaw2dsh`（0.1.7 已定，不动）。

```
catpaw2dsh
  longcat/LongCat-2.5     ← 通道 A：官方 API
  catpaw/LongCat-2.5      ← 通道 B：本地妙手复用（免费）
```

| 项 | 约定 |
| --- | --- |
| 模型行显示 | `catpaw/LongCat-2.5`（带前缀，与官方行格式统一、避免撞名） |
| 常驻显示 | 妙手未运行时该行**仍在列表中**，不动态增删 |
| 常驻的代价 | 不可用时选中发消息 → **可见错误**，不静默无反应 |
| **单一数据源** | 选择器 `catpaw/<X>` 的 `<X>` 与设置页显示的模型名**必须同源**，一处改处处变；禁止两处各写一份字面量；加测试钉住 |

### 5.1 选择器显示名为什么用「带前缀的 id」

宿主渲染模型行用的是 **`model.name`**，不是 `model.id`
（`packages/client/ui-model-selection/src/client/index.ts` → `label: model.name`）。

因此 `toPiModel()` 里 `name: info.id`：`info.id` 本身已是 `longcat/LongCat-2.5` 规范形式，
用它既带上前缀、又保证**显示名与路由键永远一致**。**只改显示名，路由键 id 不动。**

### 5.2 阶段一 GUI 结论（0.1.4 → 0.1.7）

| 决策 | 结论 |
| --- | --- |
| 官方 tab 信息密度 | 每个模型只渲染**两行**：带前缀模型名 + `上下文 / 输入 / 输出` 三个 `x.xxM` 数字；不再堆 `supportedParameters` / `pricing` 等开发者参数 |
| Key 输入位置 | **置顶**（先配 Key 再挑模型），输入框不回显已保存值 |
| 数字格式 | 按 2^20 格式化为 `x.xxM`（`formatTokens()`），取不到显示 `—` |
| 回落标注 | `detailSource === 'fallback'` 时在模型名后加极小标记，不占整行 |
| 样式 | **模块级 CSS 注入**（`styles.ts`，`data-plugin-css` 去重 + `typeof document` 守卫）；22 个 `var(--dsw-alias-*)` 均带 hex 兜底 |
| 关闭按钮 | 宿主机外壳已有自己的关闭 chrome，本卡**不渲染**关闭按钮 |
| 配置不可用时 | 显示只读提示条（`scope.unavailable`），**不静默失效** |

## 6. 明确不做（如实标注，不做假控件）

| 不做 | 原因 |
| --- | --- |
| 视频输入 | 人工已定不做；DSH 模型描述符也不支持声明 `video` |
| 上下文档位下拉 | 实测是客户端本地限制，调不了 → 标注「由妙手客户端管理」 |
| 深度思考开关 | 同上 |
| 额度 / 套餐展示 | 目标不包含 |
| 云端 API / 凭据解密 | 不需要（走本地 Agent Server） |
| 官方通道余额 | 官方无此接口，`pricing` 是单价不是余额 |
| `reasoning_effort` 多档 | 官方只支持开/关 |

**纪律**：做不到的功能如实标注，不做假开关、不做假下拉框、不把"做不到"包装成"已实现"。

## 7. 隐私

- 不读凭据文件、不解密、不接触账号信息
